# NuGet: вариант 23, этап 2

Python 3.10+, стандартная библиотека. Сборка и установка Python-пакетов не нужны.
Для защиты каждый этап находится в отдельном коммите.

## Файлы программы

- `run.py` — вход в программу.
- `src/cli.py` — запуск анализа, обработка ошибок и ввод команд.
- `src/config.py` — параметры и их проверка.
- `src/versions.py` — работа с номерами версий.
- `src/nuget.py` — HTTP-запросы к NuGet и разбор nuspec через XML.

## Запуск и параметры

```powershell
python run.py --package Newtonsoft.Json --version 13.0.3 `
    --repository https://api.nuget.org/v3/index.json
python -m unittest discover -s tests -v
```

Для настоящего NuGet укажите имя, нужную версию и
`--repository https://api.nuget.org/v3/index.json` без `--test-mode`.
`--package`, `--version`, `--repository` обязательны.
`--test-mode` выбирает файл вместо URL. `--output` задаёт PNG (по умолчанию `graph.png`).
`--ascii` включает текстовое дерево на этапе 5. Эти флаги не принимают значения.
Выходная папка должна существовать; неправильные настройки дают ошибку, код завершения 2.

Без аргументов `python run.py` открывает ручной ввод. Команды:
`analyze <те же параметры>`, `help`, `exit` (только вручную).
Пути с пробелами заключайте в кавычки и используйте прямой слеш `C:/My Files/file.json`.

## Демонстрация

```powershell
.\demo\demo.bat
```

Батник напрямую запускает Python и подаёт команды из `demo/commands.txt`.
После примеров программа остаётся для ручного ввода. Автоматического `exit` нет.
Ошибки не прерывают демонстрацию.

Этот этап выводит все прямые зависимости заданной версии по группам платформ.
URL хранилища определяется через PackageBaseAddress/3.0.0; читается точный nuspec.
Тестовый файл здесь только проверяется; его анализ появится на этапе 3.
